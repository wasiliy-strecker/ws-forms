🚀 MASTER-PROMPT: Erstellung des WordPress-Themes "ws-theme" (TYPO3/Extbase-Struktur)
1. Kontext & Referenz-System: Erstelle ein WordPress-Theme namens ws-theme im Verzeichnis wp-content/themes/ws-theme/. WICHTIG: Nutze das existierende Plugin im Verzeichnis src/wp-content/plugins/ws-forms/ als direkte technische Vorlage. Analysiere dort insbesondere die index.php (Autoloader), Classes/Init.php (Hook-Management) und Classes/Controller/BaseController.php (Rendering-Logik) und übertrage diese bewährten Konzepte auf das neue Theme.
2. Architektur & Namenskonventionen:
•
Namespace: Ws\WsTheme\ (analog zu Ws\WsForms\).
•
Prefix: Verwende durchgehend wst_ (statt wsf_).
•
Dateisystem (MVC):
◦
Classes/Controller/: Programmsteuerung (Page, Layout, Option).
◦
Classes/ControllerHelper/: Assistenten für Controller (PageHelper, LayoutHelper).
◦
Classes/Domain/Model/ & Classes/Domain/Repository/: Datenobjekte und Abstraktion.
◦
Classes/Service/: Globale Dienste (AssetService, MenuService, ConfigService).
◦
Classes/Init.php: Zentraler Einstiegspunkt für alle WordPress-Hooks.
◦
Resources/Private/: Unterordner Templates, Partials und Layouts (PHP-Views).
◦
Resources/Public/: Css, Js, Images, Fonts.
◦
functions.php: Initialisiert den PSR-4 Autoloader und ruft \Ws\WsTheme\Init::register_services() auf.
3. Kern-Funktionalitäten (PHP):
•
BaseController: Implementiere die Rendering-Logik aus ws-forms (mit assign(), renderView() und renderPartial()), angepasst auf die Pfad-Struktur eines Themes (get_template_directory()).
•
Services:
◦
AssetService: Zentrales Management für CSS/JS (Enqueueing).
◦
MenuService: Registrierung und Aufbereitung von WP-Menüs für die Templates.
◦
ConfigService: Typsicherer Zugriff auf Theme-Einstellungen (Options API).
4. Modernes JavaScript (Multi-Instanz-fähig):
•
Struktur: JS-Dateien in Resources/Public/Js/Fe/Controller/ (z.B. Page/ListFe.js, Block/HeroFe.js).
•
Dispatcher: Eine InitFe.js, die via Daten-Attributen ([data-wst-controller]) über alle Elemente iteriert und die korrekte init-Funktion aufruft.
•
Scope: Jede JS-Action muss so programmiert sein, dass sie mehrere Instanzen desselben Elements/Blocks auf einer Seite unabhängig voneinander steuern kann (Erhalt des Scopes durch Übergabe des jeweiligen jQuery-Elements).
5. Gutenberg-Integration (Dynamic Blocks): Registriere die Kategorie "WS Theme" und erstelle folgende Blöcke als Dynamic Blocks:
•
Hero / Stage, Grid / Columns, Teaser / Cards, Icon-Text-Liste, Accordion / FAQ, Testimonial-Slider, Dynamic Post Grid.
•
Das Frontend-Rendering der Blöcke erfolgt über die Controller/Template-Struktur. Jeder Block gibt das Attribut data-wst-controller="block.[name]" für das JS-Auto-Init aus.
6. Theme Options (Admin): Erstelle eine Einstellungsseite unter "Design > Theme Optionen" via OptionController für:
•
Branding (Logo, Farben), Typografie (lokale Fonts), Layout-Modus (Boxed/Full-Width), Social Media Links und Custom Scripts (Header/Footer).
7. Technische Umsetzung:
•
Erstelle eine theme.json für Gutenberg-Vorgaben (Colors, Spacing).
•
Trenne strikt zwischen PHP/JS-Logik und HTML-Darstellung.
•
Alle Pfade müssen über get_template_directory() aufgelöst werden.
